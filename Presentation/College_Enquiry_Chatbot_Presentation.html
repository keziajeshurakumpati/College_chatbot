01 / Context

A simpler way to ask about university life.

The project is a conversational enquiry assistant for Galgotias University. Students can ask about admissions, courses, fees, eligibility, scholarships, hostel, placements, and examinations in natural language.

Instead of navigating several information pages, a student submits one question through a chat interface and receives a response selected from verified dataset content, similarity matching, intent classification, or a controlled general-college fallback.

Beginner-friendly interaction

Ask “What are the fees?” or “How do I apply?” and receive a readable answer without needing to know the underlying intent labels or model terminology.

02 / Need

College information is useful only when students can find it.

Traditional enquiry friction

  • Information is scattered across different pages and departments.
  • Students repeatedly search for the same admission, fee, and course details.
  • Important topics such as hostel, scholarship, and placement information can be difficult to locate.
  • Manual enquiry takes time and is not always available when the student needs it.

The opportunity

Create one accessible conversational layer over the college enquiry information.

The assistant does not replace official records. It provides a guided first response and can direct students toward official information when programme-specific confirmation is required.

08 / NLP

TF-IDF turns words into useful features.

“What are the fees?”
→
lowercase + clean text
→
TF-IDF vector
→
model input

TF · Term Frequency

How important a word is within this question. A word appearing in the question contributes to its representation.

IDF · Inverse Document Frequency

How unique a word is across the dataset. Rare, informative terms carry more distinguishing value than common terms.

TF-IDF = term importance in this question × word uniqueness across the dataset
09 / Model

Logistic Regression predicts the enquiry intent.

Input question

Student text arrives through the Flask endpoint.

TF-IDF features

The vectorizer represents the cleaned text numerically.

Intent probabilities

The persisted Logistic Regression model scores each class.

Predicted intent

The strongest class can retrieve a verified response when confidence is trusted.

Eight model classes

admission · courses · eligibility · examination · fees · hostel · placement · scholarship

Confidence guardrail

The backend keeps ML_THRESHOLD = 0.60. Lower-confidence college-related questions can use the Groq fallback; unrelated questions are restricted.

This is classical machine learning, not deep learning.

10 / Runtime flow

Chatbot working sequence

01Student enters a question.
02React sends JSON to Flask.
03Backend normalizes text.
04TF-IDF represents the question.
05Logistic Regression predicts intent.
06Dataset response is selected.
07Groq handles college-related low-confidence cases.
08React renders the response.

Important routing behavior

The actual backend first checks common conversational phrases, then exact and similarity matches, topic keywords, domain relevance, ML confidence, and finally the Groq fallback. “Hi” is not treated as an ML intent; “hi, what are the fees?” continues as an enquiry.

13 / Evidence

Evaluation: what is available, and what is not.

Verified implementation facts

  • Persisted model artifact: LogisticRegression.
  • Persisted vectorizer artifact: TfidfVectorizer.
  • Eight intent classes are stored in intent_classes.pkl.
  • Backend confidence threshold is 0.60.
  • Dataset contains 634 cleaned rows.
Evaluation metrics are to be calculated from the final training/test split.

No reliable accuracy, precision, recall, F1-score, confusion matrix, or intent-wise held-out evaluation results were found in the repository. Numerical metrics are intentionally not invented for this presentation.
14 / Verification

Testing the real response paths

Valid college questions

  • “What courses are available?” → dataset similarity / courses.
  • “What is the admission process?” → verified admission response.
  • “What is the hostel fee?” → hostel topic response.
  • “What scholarships are available?” → scholarship response.

Conversational messages

  • “Hi”, “thanks”, “okay”, and “bye” → common-message handler.
  • Mixed messages such as “thanks, what is the hostel fee?” continue to enquiry routing.
  • “Wow”, “nice”, “great”, and “amazing” → short casual reactions.

Out-of-domain questions

“What is the weather?” and “Tell me a joke” receive a polite Galgotias University domain restriction response.

Checks performed

Local Flask API smoke tests, backend Python syntax checks, conversational regression tests, frontend TypeScript validation, and Vite production build validation were performed during project verification.

16 / Closing

A focused conversational layer for college enquiries.

The project combines a React student interface with a Flask API, a structured university enquiry dataset, and classical NLP classification.

It provides a practical path from a natural-language question to a grounded response, while keeping unrelated requests outside the college information domain.
